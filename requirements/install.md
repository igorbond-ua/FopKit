# Як запустити FopKit в інтернеті

Покрокова інструкція для людини без досвіду в адмініструванні. Робиться один раз, займає приблизно годину. Технічні подробиці — у `stack.md`.

Команди нижче копіюються повністю і вставляються в Термінал, після чого натискається Enter. Там, де в команді є слова ВЕЛИКИМИ ЛІТЕРАМИ, їх треба замінити своїми.

## Перевірка на своєму Mac

Перед викладанням в інтернет сайт можна запустити у себе. Сервер, домен і Docker для цього не потрібні: локально дані лежать у файлі `src/db.sqlite3`.

Відкрийте Термінал і виконайте:

```bash
cd /Users/igor.bondarenko/Documents/Personal/FopKit/src
DJANGO_DEBUG=1 SSL_CERT_FILE=/etc/ssl/cert.pem .venv/bin/python manage.py runserver
```

Далі в браузері відкрийте http://127.0.0.1:8000 і увійдіть як `bond` з паролем `123`. Щоб зупинити сайт, натисніть у Терміналі `Ctrl+C`.

- `DJANGO_DEBUG=1` вмикає режим розробки, тож секретний ключ і домен не потрібні.
- `SSL_CERT_FILE=/etc/ssl/cert.pem` дає Python сертифікати Mac. Без цього не працюють курс НБУ і кнопка «Оновити реквізити».

Якщо проєкт щойно завантажено з GitHub, папки `.venv` і бази ще немає. Перед першим запуском один раз виконайте в папці `src`:

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
DJANGO_DEBUG=1 .venv/bin/python manage.py migrate
```

Остання команда створює базу і користувача `bond`.

## Що знадобиться

- Код сайту на GitHub.
- Сервер в оренду — віртуальний сервер у хостинг-провайдера (наприклад, Hetzner або DigitalOcean), з дата-центром в ЄС.
- Домен — адреса сайту, наприклад `fopkit.com.ua`. Купується в будь-якого реєстратора доменів.
- Термінал на Mac: Програми → Утиліти → Термінал.

## 1. Створити ключ для входу на сервер

Ключ замінює пароль і надійніший за нього. На Mac у Терміналі:

```bash
ssh-keygen -t ed25519
```

На всі питання просто тисни Enter. Потім скопіюй відкриту частину ключа:

```bash
cat ~/.ssh/id_ed25519.pub | pbcopy
```

Тепер ключ у буфері обміну, він знадобиться на наступному кроці.

## 2. Орендувати сервер

У кабінеті хостинг-провайдера створи новий сервер:

- Система: **Ubuntu 24.04**
- Розмір: **2 ГБ пам'яті**, 1–2 процесори, від 30 ГБ диска
- Розташування: країна ЄС
- SSH-ключ: встав те, що скопіював на кроці 1
- Якщо провайдер пропонує автоматичні резервні копії сервера — увімкни. Це найпростіший захист від втрати даних

Після створення провайдер покаже **IP-адресу** сервера, щось на зразок `203.0.113.10`. Запиши її.

## 3. Направити домен на сервер

У кабінеті, де купувався домен, знайди налаштування DNS і додай запис:

| Тип | Ім'я | Значення |
| --- | --- | --- |
| A | `@` | IP-адреса сервера |

Якщо домен підключений до Cloudflare, для цього запису вимкни помаранчеву хмаринку (режим «DNS only»), інакше сертифікат HTTPS не видасться.

Запис починає діяти від кількох хвилин до кількох годин.

## 4. Зайти на сервер

У Терміналі на Mac:

```bash
ssh root@IP-АДРЕСА
```

На перше питання про довіру до сервера відповідай `yes`. Тепер усі команди виконуються вже на сервері.

## 5. Підготувати сервер

Оновити систему:

```bash
apt update && apt upgrade -y
```

Закрити все, крім входу і сайту:

```bash
ufw allow OpenSSH
ufw allow 80
ufw allow 443
ufw --force enable
```

Поставити Docker — програму, яка запускає сайт і базу:

```bash
curl -fsSL https://get.docker.com | sh
```

## 6. Завантажити код з GitHub

Репозиторій краще тримати приватним. Тоді GitHub попросить ключ доступу:

1. На GitHub: фото профілю → Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token.
2. У «Repository access» обери лише репозиторій FopKit.
3. У «Permissions» дай «Contents: Read-only».
4. Скопіюй токен. Він показується тільки один раз.

На сервері:

```bash
cd /root
git clone https://github.com/ТВІЙ-ЛОГІН-GITHUB/fopkit.git
cd fopkit/src
```

Коли попросить Username — введи логін GitHub. Коли попросить Password — встав токен. Символи при вставці не видно, так і має бути.

Код сайту лежить у папці `src`, тому всі подальші команди виконуються з `/root/fopkit/src`.

## 7. Заповнити налаштування

Створи файл налаштувань із шаблону і відкрий його:

```bash
cp .env.example .env
nano .env
```

Заповни три рядки:

- `DOMAIN` — твій домен, наприклад `fopkit.com.ua`
- `POSTGRES_PASSWORD` — довгий випадковий пароль бази
- `DJANGO_SECRET_KEY` — довгий випадковий секрет сайту

Випадкове значення для кожного з двох останніх можна отримати так. Запусти команду двічі, окремо для кожного рядка:

```bash
openssl rand -base64 48
```

Збережи файл: Ctrl+O, Enter, потім Ctrl+X.

Файл `.env` лежить тільки на сервері. Нікуди його не пересилай і не завантажуй на GitHub.

## 8. Запустити сайт

```bash
docker compose up -d --build
```

Перший запуск триває кілька хвилин. Після нього відкрий у браузері `https://ТВІЙ-ДОМЕН`. Має з'явитися сторінка входу із замочком в адресному рядку.

Якщо замочка немає або сайт не відкривається — найчастіше домен ще не встиг почати вказувати на сервер. Зачекай і спробуй пізніше.

## 9. Перший вхід

Увійди з логіном `bond` і паролем `123`.

Одразу відкрий «Кабінет» і задай новий пароль. Пароль `123` у відкритому інтернеті підбирається за секунди.

## 10. Щоденна копія бази

На сервері відкрий розклад завдань:

```bash
crontab -e
```

Якщо спитає про редактор — обери `nano`. Додай у кінець файлу рядок:

```bash
0 3 * * * cd /root/fopkit/src && docker compose exec -T db pg_dump -U fopkit fopkit | gzip > /root/backup-$(date +\%F).sql.gz
```

Збережи: Ctrl+O, Enter, Ctrl+X. Тепер щоночі о 3:00 на сервері з'являтиметься файл з копією бази.

Копія на тому самому сервері не рятує, якщо зламається сам сервер. Тому або увімкни автоматичні копії сервера в провайдера (крок 2), або час від часу забирай файли собі на Mac. У Терміналі на Mac, не на сервері:

```bash
scp root@IP-АДРЕСА:/root/backup-*.sql.gz ~/Documents/
```

## Оновлення сайту

Коли на GitHub з'явилась нова версія, зайди на сервер і виконай:

```bash
cd /root/fopkit/src
docker compose exec -T db pg_dump -U fopkit fopkit | gzip > /root/before-update-$(date +%F).sql.gz
git pull
docker compose up -d --build
```

Другий рядок зберігає копію бази перед оновленням. Якщо щось піде не так, дані залишаться.

## Якщо щось не працює

Подивитися, що запущено:

```bash
cd /root/fopkit/src
docker compose ps
```

Усі три частини — `app`, `db`, `caddy` — мають бути в стані `running` або `Up`.

Подивитися останні повідомлення сайту:

```bash
docker compose logs --tail=100 app
```

Цей текст можна скопіювати і показати розробнику або асистенту — з нього видно причину.

Перезапустити все:

```bash
docker compose restart
```
